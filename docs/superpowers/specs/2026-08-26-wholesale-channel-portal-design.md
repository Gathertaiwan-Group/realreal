# 通路商批發訂單系統設計

## 背景與目的

誠真生活正在開發藥局、生機店、蔬食店等實體通路商合作關係。目前這些通路商完全透過 LINE / 電話口頭下單，由創辦人（尹昕）手動把訂單輸入系統——沒有任何線上工具，也沒有跟零售訂單分開的紀錄，導致：

- 每筆通路商訂單都要人工二次輸入，容易出錯、耗時
- 通路商銷售數字跟零售訂單混在一起，無法單獨拉報表
- 沒有集中的通路商訂單歷史紀錄，對帳只能翻聊天紀錄

目標：讓通路商可以自己在網站上下單，同時讓創辦人日後能輕鬆拉出「單一通路商對帳明細」「通路商 vs 零售銷售排行」「全通路商總進貨量」三種報表。

## 架構決策：整合進現有網站，不做獨立系統

延伸現有 Next.js (`apps/web`) + Express (`apps/api`) + Supabase 架構，不另建獨立系統。

**理由**：通路商數量少、不需要線上金流（月結對帳）、報表需求可以用同一個資料庫的 SQL 查詢滿足。獨立系統會需要重複維護商品目錄、庫存、帳號系統，對目前規模是過度工程。

## 核心設計

### 1. 身分與登入

沿用現有 Supabase Auth + `user_profiles` 會員系統。`user_profiles.role` 新增一個值 `wholesale`（現有值：`customer` / `admin` / `editor` / `viewer`）。通路商的註冊/登入方式跟現有會員完全相同（email + 密碼），差別只在身分標記。後台可依 `role='wholesale'` 篩選出通路商帳號清單。

### 2. 批發價格表

新增 `wholesale_prices` 表：`variant_id`（FK → product_variants）+ `wholesale_price`。每個商品規格各自設定批發價，不是零售價的固定比例折扣。

**商品範圍限制**：只有「單品」（單一口味/單一規格的獨立商品，例如 50 克隨身包、300 克夾鏈袋單品）可以設定批發價；「組合商品」（例如 10 天隨身組合、30 天自選組合、3 入夾鏈袋組）**不開放批發**，`wholesale_prices` 表不會有這些商品的資料列。

判斷邏輯：通路商入口的商品列表只顯示「在 `wholesale_prices` 表裡有對應資料列」的商品規格——沒有設定批發價的商品（含所有組合商品）自動不會出現，不需要額外的「是否為組合商品」欄位去判斷，靠「有沒有批發價」這個資料本身就自然過濾掉。

### 3. 下單入口

新增 `/wholesale` 路由群組（跟現有 `/checkout` 平行），僅 `role='wholesale'` 的登入帳號可存取。流程：

1. 登入 → 商品列表（顯示批發價，非零售價）
2. 選商品、輸入數量 → 加入購物車 → 送出訂單
3. **不經過金流付款步驟**（月結制，下單當下不用付款）
4. 訂單成立後可在「我的訂單」查看歷史紀錄與狀態

### 4. 訂單資料與狀態

`orders` 表新增 `order_type` 欄位（`retail` / `wholesale`），寫死為 `wholesale`。訂單狀態走獨立的簡化流程：**待確認 → 已確認 → 已出貨**，不使用零售訂單的付款狀態機（`payment_status` 對 wholesale 訂單無意義，固定留空或設一個中性值）。

這個欄位是報表分流的關鍵：所有報表查詢都用 `order_type='wholesale'` 做第一層篩選，確保跟零售數字完全分開、不互相汙染。

### 5. 後台管理

新增 `/admin/wholesale-orders`，跟現有 `/admin/orders`（零售訂單）分開頁面，避免兩種訂單混在同一個列表造成混淆。功能：

- 檢視待確認訂單，確認/拒絕
- 標記已出貨
- 依通路商、月份篩選訂單

### 6. 報表

因為訂單都存在同一個資料庫，三種報表需求都是 `orders` 表上以 `order_type='wholesale'` 為基礎的 SQL 查詢，不需要額外的資料同步或跨系統整合：

- **單一通路商當月/累計訂單金額**（對帳用）：`GROUP BY user_id`，可篩選月份區間
- **通路商 vs 零售商品銷售排行分開看**：`order_items` JOIN `orders`，依 `order_type` 分組後各自排序
- **全通路商加總進貨量**（庫存/補貨規劃用）：`order_type='wholesale'` 的 `order_items` 依商品加總

第一階段先做成後台頁面上的篩選查詢；匯出 Excel 屬於後續加強項目，不在本次範圍內（架構本身已經支援，之後加一個匯出按鈕即可）。

## 明確排除範圍（Out of Scope）

- 組合商品的批發訂購（見上方「商品範圍限制」）
- 線上金流／下單當下付款
- 依通路商個別設定不同商品可見範圍（目前所有通路商看到同一套商品範圍與同一套批發價）
- 通路商專屬折扣碼、階梯式訂購優惠
- 報表 Excel 匯出（後續加強項目）
- 通路商自助註冊審核流程（暫時由創辦人手動建立通路商帳號並標記 role）

## 開放假設（待驗證，非阻塞）

- 目前所有通路商共用同一套批發價格表與商品範圍；若未來出現「不同通路商要看到不同商品」的需求，需要額外設計（例如通路商群組 × 商品的對應表），本次不處理。
- 通路商帳號建立方式沿用手動流程（創辦人在後台建立帳號、設定 role），不做自助申請/審核。
