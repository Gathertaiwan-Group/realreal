# 新增商品介面重設計

## 目標

讓管理員能在單一頁面建立完整商品資料，涵蓋目前商品詳情頁與資料庫已支援的欄位，並一次建立商品及全部規格。

## 欄位範圍

### 基本資料

- 商品名稱
- 網址代碼
- 商品分類
- 商品摘要
- 商品完整描述

### 圖片

- 多張圖片上傳
- 圖片排序
- 第一張圖片作為主圖
- 每張圖片可填替代文字

### 規格與庫存

- 至少一筆規格
- 規格名稱
- SKU
- 原價
- 特價
- 庫存數量
- 重量
- 自訂屬性，例如口味、容量、包數
- 可新增、複製、刪除規格

### 顯示設定

- 上架狀態
- 首頁精選
- 加購商品
- 顯示排序權重

## 介面

- 桌面版採左右雙欄。
- 左側依序放基本資料、圖片、摘要、描述與規格。
- 右側固定顯示發布設定、完成度、錯誤摘要與送出按鈕。
- 手機版改為單欄。
- 規格以卡片呈現，屬性區可展開。

## 建立流程

新增 `POST /admin/products` 專用 endpoint，一次接收商品與 variants。

1. 驗證商品欄位與至少一筆規格。
2. 驗證同次請求內 SKU 不重複。
3. 驗證特價不得高於原價。
4. 建立商品。
5. 批次建立規格。
6. 若規格建立失敗，刪除剛建立的商品。
7. 回傳完整商品 ID，前端導向編輯頁。

## 錯誤處理

- 前端送出前顯示欄位錯誤摘要。
- API 回傳可理解的 validation error。
- 建立規格失敗時執行補償刪除，避免留下沒有規格的商品。
- 網路錯誤保留表單內容，讓管理員可重試。

## 驗證

- API schema 與 rollback 單元／route 測試。
- 前端 payload builder 與規格驗證測試。
- Web lint、Web build、API build。
